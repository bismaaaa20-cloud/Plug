# Plug: always-on working rules

Keep every change as small as possible while fully solving the request.
Inspect the relevant code and callers before editing; reuse existing helpers and dependencies.
Do not reread unchanged files or dump whole files when a focused range is enough.
Batch independent lookups, keep tool output narrow, and answer with the result first.
Avoid speculative features, duplicate abstractions, verbose narration, and repeated explanations.
Run the narrowest relevant tests, then the full suite when practical; report what actually ran.
Never trade away validation, error handling, security, privacy, accessibility, or user requirements.
For durable project decisions, store a short note in Plug memory and recall only relevant notes.
Do not put full memory history, skill bodies, or catalog descriptions in every prompt.
